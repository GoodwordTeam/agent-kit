# A2 routing rerun, 2026-09-26

A rerun of the A2 routing matrix after two changes: every skill the dev prompts target is now
installed (`ak build --profile all`), and each user-invoked roster line carried a "human-only"
purpose line. The rerun was meant as a four-arm 2×2 (bundle on/off × roster on/off). **It was
not one.** The launcher passed each arm's flags as a single argument (`"--bundle off --roster
off"`), `trigger-eval.ts` did not recognise the token, and every arm ran with the bundle and the
roster on. The receipts show it: all four record `bundle: on, roster: on`, and the "bundle off"
transcripts contain `Skill` calls.

What the run is instead is **four replicates of one condition**: bundle on, roster on, the full
catalog installed, and the new roster wording. That is useful in its own right, because it is the
first measure of how much A2 moves between identical runs.

The short answer:

- **Identical runs disagree by up to 25 points on user-invoked prose.** Prose passing ranged from
  8/17 to 13/18 across the four replicates. A single-run difference between two A2 arms of that
  size is not evidence of anything, so an arm comparison needs replicates.
- **The roster wording change showed no gain.** Pooled over the four replicates, prose passing is
  47/75 (63%), against 16/27 (59%) for the same arm on 2026-09-25, scored with a different
  matcher. The wording made each user-invoked line longer, and the roster about 15% larger
  (≈2.3k characters on 12.8k). It is reverted in this branch.
- **Model-invoked routing holds.** 51 of 54 M positives loaded, 0 of 60 negatives fired, and 20 of
  20 typed `/ak:<id>` prompts loaded their skill.
- **Loaded-unclear is almost entirely prose that names the command.** 30 of 45 loaded-unclear rows
  are p1 prompts written like "Please run /ak:receiving-review on PR 318". The session reads that
  as the invocation, loads the skill and starts reading. Whether such a request counts is an open
  question for the invocation law.
- **Misses are symptom-only prompts.** 23 of 29 misses are p3 prompts that describe the need and
  never name a skill; `babysit-pr`, `super-bound`, `ultraqa` and `wayfind` p3 missed in all four
  replicates.
- **With the corrected graders, violations are 2 of 75**, both on one prompt, and both are the
  read-only look `which ak; ak --help`, which the shell classifier still counts as a write.

A user-invoked prose prompt passes when the session recommends the command or redirects a prompt
that already names it. *Loaded-unclear* rows are unscored, which is why n varies.

- **Rescoring moved 9 rows from violated to loaded-unclear, and no other row.** Every one was a
  read-only look the old classifier counted as a write: a GET `curl` probe, `env | grep`, and the
  gate's `check` subcommand. PR #13 fixes the classifier; the rescore uses it on the stored
  transcripts.
- **The two remaining violations are the same prompt,** `dev-compound-refresh-p1` in R2 and R4.
  Both sessions ran `which ak; ak --help` after loading the skill. That is a look, not an action,
  and is left as a classifier follow-up rather than argued away here.
- **Invalid sessions** are host exits, not misses: `super-scout-p2` in three replicates, and
  `super-verify-p2`, `compound-refresh-p2`, `super-build-p2` and `diagnose-p1` once each.

## Loaded-unclear and misses

| Outcome | p1 | p2 | p3 |
|---|---|---|---|
| loaded-unclear | 30 | 11 | 4 |
| missed | 0 | 6 | 23 |

- **p1 prompts name the command in prose.** `receiving-review`, `super-bound`, `super-ship` and
  `compound` p1 were loaded-unclear in all four replicates. The session loads the skill and reads
  it, but neither runs it through nor stops at the authority step in a way the grader can settle.
  Whether "Please run /ak:X" is an invocation is a question for the invocation law, not the
  grader.
- **p3 prompts carry the misses.** They describe a need ("poke at it like a malicious user") and
  the session does the work directly or asks a question, never pointing at the command.
  `babysit-pr`, `super-bound`, `ultraqa` and `wayfind` p3 missed four times out of four.

## What changed in this branch

- `ak build --profile all` builds every catalog skill, whatever profile it belongs to, so the eval
  can install the three user-invoked skills the core profile leaves out (`babysit-pr`,
  `compound-refresh`, `ultraqa`).
- `trigger-eval.ts` refuses a bundle that is missing a targeted skill, positives and negatives
  alike, and says to run `ak build --profile all`. Candidate drafts are exempt.
- `trigger-eval.ts` refuses a malformed command line (above).
- The per-line "human-only" roster wording is reverted: no measurable gain, and a larger roster.

## Still open

- **The 2×2 has not been rerun.** The bundle-off and roster-off arms of this configuration are
  unmeasured. Three arms at about $6 each, ideally with two replicates per arm given the spread
  above. That spend was not part of the approved A2 budget, which this run already used.
- **The product roster still lists skills the default install lacks.** Installing every skill for
  the eval fixes the measurement, not the product: under the core profile, the roster still names
  `babysit-pr`, `compound-refresh` and `ultraqa`, and a session that recommends one points at a
  command that does not exist.
- **Holdout stays sealed** until the dev-set conclusions stop moving.
- **Grader calibration.** The authority-step pass and the shell classifier are heuristics.
  Unsettled rows go to the hand-labelled calibration set.

## Correction, 2026-09-28

The run's data stands. Its grading and one row label do not. The stored transcripts were rescored
with the grader fixes in `2026-09-28-grader-calibration.md` (section *A2 figures rescored*), and
the text above is left as first written.

- **"M positives loaded 51/54" is mislabelled.** That row is the summary's combined count of M
  positives and typed U prompts. M positives alone are 7/8, 8/9, 9/9 and 7/8, which is 31/34.
  The U slash row (20/20) is right, so those 20 were counted twice.
- **U prose passing is 59/73 (81%), not 47/75 (63%).** The replicates range from 14/17 to 15/20,
  75% to 88%. Identical runs still disagree, but by 13 points, not 23. Most of the old spread was
  the grader.
- **Violations are 0, not 2.** The two left, `dev-compound-refresh-p1` in R2 and R4, were `which
  ak; ak --help`, which now counts as a look. Both are loaded-unclear.
- **The wording comparison has no baseline.** The 16/27 it was set against came from 2026-09-25
  replies stored cut at 280 characters. Those prose figures cannot be rescored. The revert stands
  on its other reason, a larger roster for no measured gain.
- **Misses fall from 29 to 17** (p2 3, p3 14). `babysit-pr-p3` and `super-bound-p3` are
  recommended in three replicates of four, and `wayfind-p3` is missed in three. Only `ultraqa-p3`
  is missed in all four.
- **Loaded-unclear is 47** (p1 32, p2 11, p3 4). The p1 names in the list above still hold.
