# Updating a recorded strategy

Read before touching a strategy page that already exists. It decides whose shape the page is in, what
an update run changes, and what it leaves alone.

## Meaning is the contract; the shape belongs to whoever created the page

A page this skill created is in the house shape of the strategy template. A page someone else wrote,
by hand or through another tool, is read by meaning: a section counts as present when the page
expresses it anywhere, under any heading or in prose. Changes to such a page are additive or minimal
and in its own idiom. It is never restructured into the template, never given headings it did not
ask for, and never given a second copy of a meaning it already carries.

Two things are never edited:

- A section carrying an author-approved marker, an HTML comment naming a tool and the approval, for
  example `<!-- <tool>: author-approved 2026-07-10 -->`.
- A page the human does not own.

For either, report the conflict and leave it to its owner. The worst outcome is turning someone's page
into this template and breaking what already reads it.

## Whose page is it: decide before editing

Decide from the page and its revision history in the knowledgebase, never from memory of an earlier
run:

- **Solely this skill's** when every revision was published by this skill, every `##` heading is one
  of the template's (Purpose, Positioning, Users, Boundaries, Key metrics, Tracks, Milestones, Brand),
  and no other tool's marker appears. Such a page is maintained in house shape on every publish:
  sections in the template's order, a missing required section offered.
- **Multi-writer** the moment any revision came from elsewhere, or any other heading or marker is
  present. This skill's own sections are still its to revise, but nothing is reordered and nothing
  foreign is restyled or edited. If what this run learned makes someone else's section false, make
  the smallest edit that keeps its intent true and say so in chat.

## The update run

1. Summarize the page in three to five lines so the human sees what is on record.
2. Check for drift. Compare every section with the grounding: stated intent, structure, recent
   commits, and the product's other pages. Name any section the evidence suggests is stale, with the
   evidence, as a candidate and never as a verdict.
3. Revisit the section the focus named. With no focus, ask which section to revisit, listing drift
   candidates first: Purpose, Positioning, Users, or metrics, tracks, boundaries and the rest.
4. Re-interview each revisited section with full pushback, as on a first run. Existing weak content
   is not rubber-stamped because it is already written.
5. Leave every other section's content exactly as it is.
6. A house-shape page missing Boundaries: offer to add it; never add it silently. A page not in house
   shape gets no section it did not ask for, except that a new section of this skill's own uses the
   template heading, and a meaning already carried under another heading is merged there.
7. Draft, show, take one edit round, then publish a new revision of the same page.

When every section is confirmed as still accurate, publish nothing.
